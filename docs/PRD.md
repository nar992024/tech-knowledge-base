# Tech Knowledge Base PRD

## 프로젝트 개요

- **프로젝트명**: Tech Knowledge Base
- **목적**: Notion을 CMS로 활용한 공개 IT 기술 학습 사이트. 검증한 자료를 순서가 있는 코스로 묶어 무엇을 어떤 순서로 볼지 안내하고, 나머지 자료는 자료실에서 찾을 수 있게 한다.
- **대상 사용자**: AI 코딩과 에이전트 개발을 공부하려는 개발자
- **공개 범위**: 누구나 로그인 없이 볼 수 있는 공개 사이트
- **CMS 선택 이유**: Notion API를 활용하여 비개발자도 콘텐츠 관리 가능

### 성공 기준

- 공개한 코스의 모든 단계가 `검증 완료` 링크로 구성되어 있다.
- 방문자가 코스 목록에서 자신에게 맞는 코스를 고르고, 코스 상세에서 다음에 볼 자료를 바로 알 수 있다.
- 공개 링크 전체를 자료실에서 검색과 필터로 찾을 수 있다.
- Notion에서 수정한 내용이 코드 변경 없이 5분 안에 사이트에 반영된다.
- Notion 장애가 발생해도 이전에 조회한 내용을 계속 보여 준다.
- 배포 전 링크 점검에서 열리지 않는 공개 링크가 없다.

## 주요 기능

1. **Notion 콘텐츠 연동**: 코스 DB와 링크 DB를 조회해 사이트에 표시한다.
2. **코스 목록**: 코스명, 소개, 대상, 난이도, 단계 수를 카드로 보여 준다.
3. **단계별 학습 경로**: 코스의 링크를 순서대로 보여 주고, 각 자료를 왜 봐야 하는지와 이용 조건을 안내한다.
4. **자료실**: 공개 링크 전체를 키워드 검색과 카테고리, 유형 필터로 찾는다.
5. **데이터 품질 관리**: 초기 데이터 입력 스크립트와 링크 점검 스크립트로 Notion 데이터를 관리한다.

## 기술 스택

- **Frontend**: Next.js 15, TypeScript
- **CMS**: Notion API (`@notionhq/client`)
- **Styling**: Tailwind CSS, shadcn/ui
- **Icons**: Lucide React
- **데이터 검증**: Zod

## Notion 데이터베이스 구조

코스 DB와 링크 DB 2개를 사용한다. 새 코스나 링크를 추가할 때 코드를 수정하지 않는다.

### 코스 DB

| 필드      | 타입     | 설명                        |
| --------- | -------- | --------------------------- |
| 코스명    | Title    | 화면에 표시할 코스 이름     |
| slug      | Text     | URL에 쓰는 고유 영문 식별자 |
| 순서      | Number   | 코스 목록의 표시 순서       |
| 난이도    | Select   | `입문`, `중급`, `고급`      |
| 소개      | Text     | 코스에서 배우는 내용        |
| 대상      | Text     | 코스가 맞는 사용자          |
| 선수 지식 | Text     | 시작 전에 필요한 지식       |
| 공개 여부 | Checkbox | 체크한 코스만 사이트에 표시 |

### 링크 DB

| 필드      | 타입     | 필수 | 설명                                                                                    |
| --------- | -------- | ---- | --------------------------------------------------------------------------------------- |
| 제목      | Title    | 필수 | 화면에 표시할 링크 제목                                                                 |
| 링크 ID   | Text     | 필수 | `IT-001` 형식의 고유 식별자. 초기 데이터 재입력과 자료실 정렬의 기준                    |
| URL       | URL      | 필수 | 원본 링크 주소                                                                          |
| 목적      | Text     | 필수 | 방문자에게 보여 줄 자료 설명. 내부 메모는 쓰지 않음                                     |
| 카테고리  | Select   | 필수 | 자료실 필터용 주제 분류 10종                                                            |
| 유형      | Select   | 필수 | `문서`, `강의`, `영상`, `아티클`, `게시물`, `저장소`, `도구`, `논문`                    |
| 검증 상태 | Select   | 필수 | `미검증`, `검증 완료`. 원문 내용을 직접 확인한 뒤 `검증 완료`로 변경                    |
| 공개 여부 | Checkbox | 필수 | 체크한 링크만 사이트에 표시                                                             |
| 이용 조건 | Select   | 선택 | `무료`, `유료`, `로그인 필요`, `파트너 전용`. 확인하지 못했으면 비워 두고 표시하지 않음 |
| 코스      | Relation | 선택 | 코스 DB 연결. 링크 1개는 코스 1개에만 속함                                              |
| 순서      | Number   | 선택 | 코스 안에서의 단계 번호. 코스를 연결하면 필수                                           |
| 난이도    | Select   | 선택 | `입문`, `중급`, `고급`. 코스를 연결하면 필수                                            |
| 언어      | Select   | 선택 | `한국어`, `영어`                                                                        |
| 예상 시간 | Number   | 선택 | 분 단위 예상 학습 시간. 값이 있을 때만 표시                                             |

**카테고리**: Claude Code·Claude 활용, AI 에이전트 엔지니어링, AI 코드 리뷰·품질, 테스트 자동화·프론트엔드, DevOps·인프라, 개발 도구·IDE, AI 업무 자동화, 보안, 온톨로지·지식그래프, 강의·자격증

### 공개 규칙

- **코스**: `공개 여부`를 체크한 코스만 표시한다. 비공개 코스의 주소는 404로 처리한다.
- **코스 단계**: `공개 여부`를 체크하고 `검증 완료`인 링크만 표시한다.
- **자료실**: `공개 여부`를 체크한 링크를 모두 표시하고, `검증 완료` 링크에만 배지를 붙인다. `미검증` 배지는 표시하지 않는다.
- **안내 문구**: 자료실에 "외부 자료의 내용은 변경될 수 있으며, 검증 완료 표시가 없는 자료는 내용을 직접 확인하지 않았습니다"를 표시한다.

## 화면 구성

- **코스 목록 (`/`)**: 프로젝트 소개와 코스 카드 그리드. 카드에 코스명, 소개, 대상, 난이도, 단계 수를 표시하고, 자료실로 가는 링크를 둔다.
- **코스 상세 (`/courses/[slug]`)**: 코스 소개, 대상, 선수 지식과 번호가 붙은 단계 목록. 각 단계에 제목, 목적, 난이도, 유형을 표시하고, 값이 있으면 이용 조건, 언어, 예상 시간도 표시한다. 원본 링크는 새 탭에서 연다.
- **자료실 (`/library`)**: 키워드 검색, 카테고리 필터, 유형 필터, 초기화 버튼과 링크 카드 그리드. 검색 조건은 URL 쿼리에 저장해 공유할 수 있게 하고, 코스에 속한 링크에는 코스로 가는 링크를 표시한다.
- **결과 없음**: 자료실 검색 결과가 없을 때 조건 변경과 초기화를 안내한다.
- **빈 코스**: 공개 코스에 표시할 단계가 없으면 코스 목록에서 숨긴다.
- **로딩**: 코스 목록과 자료실은 데이터 조회 중 스켈레톤을 표시한다. 코스 상세는 없는 주소에 HTTP 404를 정확히 응답하도록 조회가 끝난 뒤 화면을 보낸다.
- **404**: 없는 주소나 비공개 코스에 접근하면 코스 목록으로 돌아가는 링크를 보여 준다.
- **조회 오류**: 표시할 캐시도 없을 때만 안내 문구와 다시 시도 버튼을 보여 준다.

## 데이터 처리

- **조회**: 기존 `src/lib/notion.ts`의 data source 조회 방식을 재사용하고, `dataSources.query`의 페이지네이션을 끝까지 순회한다. `NOTION_API_KEY`는 서버에서만 사용한다.
- **캐싱**: `unstable_cache`를 사용하고, 5분 안에 반영되도록 재검증 주기는 240초로 한다. 만료 후 첫 요청은 이전 내용을 받고 재조회를 시작하며, 다음 요청부터 새 내용을 받는다.
- **장애 대응**: 재검증에 실패하면 마지막으로 성공한 캐시를 유지하고 오류를 로그에 남긴다.
- **행 검증**: Notion 응답을 Zod로 검증한다. 필수 값이 없거나 URL이 잘못된 행, 코스 연결이 있는데 순서나 난이도가 없는 행은 화면에서 제외하고 링크 ID와 함께 로그를 남긴다. 한 행의 오류로 페이지 전체가 실패하지 않게 한다.
- **순서 중복**: 코스 안에서 순서가 같으면 링크 ID 순으로 표시하고 로그를 남긴다.
- **환경 변수**: `NOTION_API_KEY`, `NOTION_DATABASE_ID`(링크 DB), `NOTION_COURSE_DATABASE_ID`(코스 DB). `ADMIN_PASSWORD`와 `SESSION_SECRET` 검사는 `src/lib/env.ts`에서 제거한다.
- **로컬 검증**: `CONTENT_SOURCE=seed`이면 Notion 대신 `data/seed.json`을 읽는다. E2E 테스트와 로컬 확인에만 사용한다.

## 운영 스크립트

- **초기 데이터 입력 (`scripts/seed-notion.ts`)**: `data/seed.json`을 Notion에 입력한다. 코스는 `slug`, 링크는 `링크 ID`로 기존 행을 찾으므로 여러 번 실행해도 중복되지 않는다. 쓰기 전에 DB 구조를 확인해 다르면 중단하고, Notion에서 수정한 내용을 지키기 위해 기존 행은 `--update`를 지정했을 때만 덮어쓴다. `--dry-run`으로 미리 볼 수 있다.
- **링크 점검 (`scripts/check-links.ts`)**: 공개 링크의 응답을 확인해 404, 403, 주소 변경, 연결 실패를 보고한다. 403과 X 링크는 봇 차단이나 로그인 때문일 수 있으므로 자동으로 수정하지 않고 사람이 확인한다. 배포 전에 실행한다.

## 품질 요구사항

- **반응형**: 모바일, 태블릿, 데스크톱에 대응하고, 버튼 등 터치 대상의 높이는 44px 이상으로 한다.
- **테마**: 라이트 모드와 다크 모드를 지원한다.
- **접근성**: 키보드로 모든 기능을 사용할 수 있고, 포커스 표시와 시맨틱 마크업을 갖추며, 새 탭 링크임을 스크린 리더에 알린다.
- **검색 노출**: 페이지별 title, description, Open Graph 이미지, `sitemap.xml`, `robots.txt`를 제공한다. 비공개 코스는 sitemap에 넣지 않는다.
- **외부 링크**: `rel="noopener noreferrer"`를 사용한다.
- **테스트**: 데이터 변환과 공개 규칙은 단위 테스트로, 코스 목록에서 원본 링크까지와 자료실 검색은 Playwright E2E 테스트로 확인한다.

- 코스 목록, 코스 상세, 자료실, 404, 오류 화면
- 공개 규칙과 Notion 응답 검증
- 240초 캐싱과 장애 시 캐시 유지

- 검색 노출, 접근성, 다크 모드, 테스트
- 기존 견적서 코드 정리
- 코스 5개, 24단계의 원문 검증

### 제외

- 로그인 및 사용자별 기능
- 관리자 화면 (콘텐츠 관리는 Notion에서 수행)

- 다국어 지원
- 링크 점검 자동 실행 (MVP에서는 배포 전 수동 실행)

## 구현 단계

1. **기존 코드 정리**: 견적서 관련 코드와 의존성을 삭제하고 환경 변수 검증을 수정한다. 빌드가 통과하는 상태를 먼저 만든다.
2. **Notion 준비**: 코스 DB와 링크 DB를 만들고 Integration을 연결한 뒤, 초기 데이터 입력 스크립트를 실행한다.
3. **데이터 계층 구현**: 타입과 Zod 스키마, 조회, 캐싱, 공개 규칙을 구현하고 단위 테스트를 작성한다.
4. **화면 구현**: 코스 목록, 코스 상세, 자료실, 상태 화면을 구현한다.
5. **콘텐츠 검증**: 코스 링크 20개를 확인해 `검증 완료`로 바꾸고, 목적, 난이도, 예상 시간을 다듬는다.
6. **품질 마무리**: 메타데이터, 접근성, E2E 테스트를 완료한다.
7. **검증 및 배포**: `npm run check-all`, `npm run build`, 링크 점검을 통과하고, Notion 수정 내용이 반영되는지 확인한 뒤 Vercel에 배포한다.

## 운영 안내

- **링크 추가**: 링크 DB에 행을 만들고 필수 필드를 채운 뒤, `공개 여부`를 체크한다.
- **코스에 넣기**: 원문을 확인해 `검증 완료`로 바꾸고, `코스`, `순서`, `난이도`를 입력한다.
- **코스 추가**: 코스 DB에 행을 만들고 `slug`와 소개를 입력한 뒤, 링크를 연결하고 `공개 여부`를 체크한다.
- **링크 숨기기**: 행을 지우지 않고 `공개 여부`를 해제한다.

## 미해결 항목

- **코스 링크 검증**: 코스 24단계 중 20개가 `미검증`이다. 이 링크는 검증 전까지 사이트에 표시되지 않으므로 공개 전에 확인해야 한다.
- **X 게시물 확인**: `IT-040`, `IT-052`는 X 게시물이다. 자동 조회로 읽지 못할 수 있어 브라우저에서 직접 확인이 필요할 수 있다.
- **`IT-004`와 `IT-062`**: 둘 다 Anthropic 학습 사이트로 내용이 겹칠 수 있다. 운영 중인 강좌가 같은지 확인해 하나를 비공개로 전환할지 정한다.
- **이용 조건 공란**: 제품과 서비스 10개는 무료 여부를 확인하지 못해 비워 두었다.
